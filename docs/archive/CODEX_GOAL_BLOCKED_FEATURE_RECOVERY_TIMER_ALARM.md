## A. Outcome and user-visible contract

Recover the three *specific* blocked features from the merged PR #1461 program, finish their dependent ZIP feature only when its real safety guarantees hold, add first-class visual Timer/Alarm selection without breaking existing typed input, and obtain focused native/GUI evidence.

1. **Persistent utility sizing:** resizable everyday tool dialogs remember a user-chosen preferred size across close/reopen and application restart; genuine manual resize still works; clamping to a smaller viewport never destroys the larger preference; Reset restores default. Only size—not position/content/layout/workspaces—is stored.
2. **Unicode Inspector UI:** expose the already-accepted pure Unicode inspection domain through a local command/dialog, with explicit text/Paste/Clear/Copy and a virtualized list whose **entire last result row** can actually be scrolled into the clipped visible region under Compact/Comfortable and large text scales.
3. **ZIP extraction:** safely bind the opened archive and destination root and resist reparse/junction/path substitution, with identity-bound no-clobber publication. Only after proof, stream supported entries within actual byte/CRC/EOF/resource limits, support cancellation/retirement, then expose the selection/extraction UI. Do **not** enable extraction on lexical checks alone.
4. **Timer/Alarm time pickers:** Keep free-text entry and existing query commands, but add direct, keyboard-accessible selection controls. Timer exposes hours/minutes/seconds as a duration selector; Alarm exposes local 24-hour hour/minute selection (`12:04`, `15:09`) and an accurate next-occurrence preview. A time without a date schedules the **next strictly future occurrence**, using actual local time-zone rules rather than naive 24-hour subtraction. Preserve explicit day-offset/date forms and current persistence/sound/name behavior.
5. **Native acceptance:** Build/run the current app under an isolated profile and verify what the environment truly supports. GUI assertions cannot be inferred from unit tests, an application build, or merely listing a window. Filesystem proof is independent of GUI tool availability.

**No silent downgrade:** A failed mandatory safety/GUI acceptance gate produces `PARTIAL`/`BLOCKED` with its exact evidence. Other independent work continues from the safe committed tip. Program checkpoint closure does not mean full feature completion.

## C. Approved behavior and engineering decisions

### C1. Geometry and settings

- A **single canonical versioned, local-only size preference** keyed by stable tool **type**, not by document name/path/query/title; store only validated finite logical `(width,height)` and optional reset/tombstone state. Use a bounded allowlist or strictly bounded existing registry. Existing and unknown JSON fields must remain compatible. Preserve normal default sizes if no saved preference.
- Keep three concepts distinct: **preferred size** (durable), **applied/clamped size** (current screen), **observed size** (current frame). A smaller viewport/DPI scaling must not overwrite the preferred size. Only an actual completed user resize/close/controlled size-change event may update durable preference; never infer user intent from auto-layout or first-frame measurement.
- Restore exactly **once per opening/instance or appropriate revision**; normal edge/corner grip must remain resizable on subsequent frames. Prove height **and** width. No per-frame `fixed_size`, continual forceful `resize`, or impossible min/max. Use a content/chrome adapter only with measurable, demonstrated egui semantics; do not patch egui/vendor internals.
- Persist with `Settings::update`/existing transactional ownership, bounded/debounced/coalesced updates, no per-paint disk writes. Integrate with `SettingsSaveIntent` general draft mapping/rollback without lost asynchronous changes or rollback of a newer size. Failed saves remain visible/retryable, not falsely committed.
- Migrate current local size fields to adapters, not second preference stores. Diff's existing body dimensions need a correct outer/body conversion and must not accidentally activate Diff session/position persistence. Clipboard Modify's clamped close writer is a legacy fallback only until migrated. Preview, Regex, XML, QR and standard resizable dialog kinds use the same stable preference through bounded adapters. Reserve `unicode-inspector` and `zip-extractor` keys without implying their features are present before accepted UI.
- Include the ledger's full **ordinary resizable dialog inventory**, check actual `resizable` configuration at implementation time, and record `implemented`, `existing_equivalent`, or `excluded_with_reason` per item. Exclude main launcher geometry, radial/screen-draw/capture overlays, native OS pickers, fixed-size/alarm dialog if actually fixed, ephemeral confirmations and transient tooltip panels. Exclude actual nonresizable kinds rather than silently making them resizable.
- Explicit Reset to default, corrupt/NaN/infinite/negative/missing data, legacy migration, independent instances, stale writes, multi-monitor/viewport bounds, density/text-size changes, no unwanted focus/Jump changes.

### C2. Unicode UI and command

- Use the existing `inspect` model **without altering normalized semantics**. Text is **session-only**, kept out of saved settings, query history, logs and debug strings. Open action is a **payload-free local GUI** route (suggested `unicode:open` only after inspecting namespace collisions). Headless/automatic origins must refuse without fallback or leaking input.
- Input is explicit `TextEdit`; **Paste** reads clipboard only on a real user click/action, at most once, retaining previous input on error. **Clear** is explicit. If the pinned egui paste event loses CRLF bytes, do not claim byte-for-byte preservation from that implicit route; present a clear explicit-Paste alternative without stealing unrelated widget events.
- Display scalar count, extended grapheme count, bytes, code point `U+XXXX`, name or honest unavailable name, UTF-8/UTF-16 units, byte/scalar indices, line/column and flags. Show the **actual distinct Unicode-data version** provenance. Escape/control invisibles in labels, keep selection and copy meaning unambiguous; never copy escaped markup when original bytes were requested.
- Virtualize up to **65,536 rows** with current theme density, typography, DPI and real minimum widget height. Use actual measured/contracted row stride and scroll clip bounds. End-of-list selection/scroll must reveal the **entire last row** under Compact/Comfortable, normal/200% typography, narrow/wide windows, expansion of details and after input replacement. Stable ID/scroll resets prevent stale row-target remapping. Do not remove/change the last-row test merely to pass.
- Apply C01 canonical dialog sizing if available; otherwise create a normally resizable window **without a new competing persistence store** and label size-persistence acceptance as dependent. Register Jump targets only for visible actionable fields/buttons. No background worker or clipboard monitoring required for bounded pure analysis.

### C3. ZIP safety, extraction and UI (gated)

- Preserve existing `ArchiveCatalog`, `ArchiveRevision`, `ArchiveEntryId`, `ArchiveLimits`, `ExtractionPlan` and lexical refusal semantics. The plan is **not permission to write**. Treat old `archive/native.rs` source/patch as unaccepted reference only.
- Maintain stable archive handle/identity through catalog→plan→payload read/effect; verify physical entry ordinal, source revision and source length/identity. Reject changed/removed/replaced source. Do not reopen the archive by path after admission and assume it is the same object.
- Bind destination root and each descendant to **held, no-follow directory/file capabilities**. Prove no escape via `..`, absolute/drive/UNC/ADS/device/reserved names, collisions, junction/reparse/ancestor swap, and no-clobber target arrival **between preview and effect**. Use a supported existing native Windows operation (checked handle-relative/no-replace semantics), not path-only `fs::rename`/`copy` fallback and not exclusive access relaxations to make tests pass. Never write outside owned fixture root for proof.
- For the prior `FilesystemLoop` vs `InvalidData` blocker, preserve **raw Win32/NTSTATUS, operation and path/component identity**, classify it as an explicit *safe refusal* only if the observed effect and actual held-root/sentinel checks prove no escape and no target overwrite. A different typed error name is not itself proof. Run both previously failing **root** and **descendant** mutation/placement cases to their terminal assertions. No second invented native FFI framework, elevation, ACL change, security-policy modification or vendor patch.
- After M3-A passes and independent review accepts it, implement the narrow previously designed **Stored (method 0)** extraction subset, reporting Deflated/encrypted/unsupported entries visibly and refusing them rather than decoding through an unproven path. Reuse existing `zip` metadata/physical ordinals and only expand compression support if the current original accepted contract explicitly requires it and separately proves its bounded decoding. No implicit support claims for all ZIP formats.
- Stream fixed-size chunks (target 64 KiB; no entire-entry buffer). Enforce **actual** per-entry 2 GiB and aggregate 8 GiB limits, actual count/ratio/supported format constraints, CRC/integrity, exact EOF and short/overlong data, cancellation, journal/partial report and bounded progress. Validate before publication; use owned CREATE_NEW stage, flush/sync and handle-bound no-replace finalization. Keep fully published files on a partial failure only when reported, and delete **only owned incomplete stages**. No false atomic rollback promise.
- Worker ownership: request→ack→terminal outcome→join/handle/buffer retirement, checked across cancelled/blocking reads and repeated starts/close/reopen. Do not claim that an `AtomicBool` or natural completion proves cancellation of a pending native operation. If the current `zip` destructor/runtime cannot be safely retired under the required constraints, refuse activation and report that exact blocker.
- Only then expose Open ZIP, catalog filtering, physical entry selection, destination picker, explicit conflict/limit/unsupported preview, Extract/Cancel, truthful partial/error report and close/reopen cleanup. No output writes during browse/preview. No UI actor may bypass the M3-A/B safety capability. No stored archive paths/contents in history. Depend on C01 size helper only when accepted; otherwise preserve ordinary bounded resizing without alternate state.

### C4. Timer/Alarm picker and next-occurrence behavior

- Preserve `timer`, `alarm`, `timer add`, `timer list`, `alarm list`, pause/resume/cancel, command parser and actual action protocols. Existing `timer` and `alarm` routes already open the shared dialog. The picker is a **dialog UI control**, not a different command syntax or external system clock picker; typed input remains supported.
- **Timer:** alongside existing duration text, provide a compact egui hours/minutes/seconds selector (e.g. small `DragValue`/popup/spinner controls, bounded segments) with keyboard/Jump focus and accessible labels. Picker changes produce a canonical duration string recognized by `parse_duration`; valid typed strings populate the selection without accidental modification. Timer duration is strictly positive and within safely checked arithmetic; invalid, negative, zero and overflow cases show a meaningful inline error and do not create a timer. Preserve named timers, sound/Play, focus, Start/Cancel and pause/resume behavior. No unnecessary interval/preset scheduling framework.
- **Alarm:** offer 24-hour (`00:00`–`23:59`) hour/minute controls beside the existing text field; entering `12:04` or `15:09` is valid and **still works without picker interaction**. Selection updates the matching text, including preserving an existing valid `Nd` or `YYYY-MM-DD` prefix when the user is editing that explicit date; never silently erase explicit date intent or autocorrect malformed text. If a date prefix is invalid, leave the error visible until corrected or the user explicitly chooses next-occurrence mode.
- **Strict next occurrence:** no-date HH:MM means the earliest valid local wall-clock occurrence **strictly later than the instant at Start**. If the desired minute is today and ahead, choose today; if already passed or equal at second-level, choose tomorrow or the next possible valid day. Recompute at Start, not just from a stale preview. If local time jumps forward and that time does not exist today, choose the next day on which the requested HH:MM exists (bounded finite search, otherwise informative refusal); for a backward fold, select the earliest of the two offset-distinct occurrences that is strictly after now. **Explicit absolute/date-offset alarms** target that date and must refuse nonexistent/past requested wall time rather than silently schedule now. Ambiguous explicit date picks the earliest future valid occurrence on that date. Show the actual resolved local date, HH:MM and offset/zone when needed; verify picker/text/preview/deadline are consistent.
- Implement one testable checked scheduling/resolution owner in `src/plugins/timer.rs`, with an injected `now` and explicit `chrono::LocalResult`/timezone mapping seam for deterministic DST-gap/fold tests. Separate parse/resolve/commit. Use an absolute timezone-aware deadline and checked positive duration; the persisted `end_ts` must equal the resolved target instant's Unix seconds (not an accidentally truncated `start_ts + duration.as_secs()` off-by-one), while the in-process monotonic deadline tracks the same target. Do not rely on subtracting two `NaiveDateTime`s across a DST transition. Preserve `SavedAlarm` JSON fields, epoch end timestamp and current active-timer/heap-generation semantics. Propagate invalid scheduling errors to GUI, leave dialog open with inline message, and use the same checked path for typed action commands (`src/actions/timer.rs`), without changing unrelated external action protocols.
- Show live **"Next alarm: ..."** preview that agrees with Start. Invalid hour/minute, bad explicit date, overflow, missing timezone occurrence and persistence errors must not silently close the dialog or register a phantom success. Do not add recurrent alarms, OS notification services, background polling, altered sound policy or new persisted picker preferences.
