1. Exact Shift+Alt+Win+End is tested deterministically through the production invocation adapter with fake time. Do NOT globally synthesize the real Win-key chord by default.
2. Headless Designer tests feed egui RawInput/pointer/key events into the ACTUAL production Designer viewport_ui and use AccessKit semantic bounds/state.
3. Add an opt-in Windows `radial_acceptance` runner. It launches a source-matched multi_launcher.exe in an isolated temp profile, uses a harmless configured native test chord through SendInput, uses UI Automation where available, and validates at least one real pointer click plus Tab through the native Designer client path.

Do not create test-only “set final state to success” bypasses. Test input may enter at explicit real boundaries and reports may read state, but the behavior under test must traverse production owners.

NATIVE RUNNER

- Identify windows by child PID + semantic title/role, not global title alone.
