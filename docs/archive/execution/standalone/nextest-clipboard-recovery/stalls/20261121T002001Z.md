## Safety gate and evidence classification

Source inspection after the default-stack action test showed that this test opens Clipboard Modify's Help section. `open_clipboard_modify_section` calls `open_section`; on first open, `open_section` calls `load_clipboard`, which invokes `service.read_text_for_modify()`. `LauncherApp::new` leaves the test clipboard override as `None`, and the dialog's default hosted-effects state is `None`, so this path uses the production clipboard service. Thus the requested 16 MiB rerun would read the host clipboard despite selecting Help. The exact unrun command was the library command above with:

```powershell
$env:RUST_MIN_STACK = '16777216'
cargo nextest run -p multi_launcher --lib --locked --offline --no-fail-fast --retries 0 --status-level pass --final-status-level fail --color never -E 'test(=gui::actions::tests::specialized_actions_ignore_query_override_before_dispatch)'
```

Expected for A1: execute the selected test under a controlled larger stack and record its result. Actual: deliberately not executed after discovering the real clipboard-read path; no exit code or runtime result exists. The default-stack attempt occurred before this path was established and aborted without stage instrumentation, so whether it reached the read is unknown. Its test body performs no transform, commit, or undo, and no clipboard content was printed, but I cannot claim the default attempt did not read clipboard data. No further clipboard-related run was made.

Evidence supports a shared test-thread stack-capacity problem in the five safe comparisons: each aborted at the default stack and completed at 16 MiB, and the keyboard-navigation default failure reproduced once. The identical default abort across GUI rendering, actions, notes, settings-save, and an integration test is inconsistent with six independent assertion defects. This is diagnostic evidence, not proof of the root cause or of the cause of all 456 reported aborts. Oversized/shared `LauncherApp` construction or fixture stack use remains a hypothesis; genuine deep recursion is not ruled out for unsampled tests.

Relevant fixture note for a later approved change: the root-list and settings-save helpers set Paste Sequences' `next_hotkey` and `cancel_hotkey` to `None`; the selected `gui::actions` helper, notes helper, and `hide_after_run` app fixture do not. This does not establish a stack-overflow cause and was not changed in M0.
