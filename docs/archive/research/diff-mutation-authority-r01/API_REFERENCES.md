## Interpretation boundaries

Native IDs can compare opened objects; contents can still differ across time, and names/parents/destinations are distinct. The candidate stronger contract therefore needs explicit guard lifetime and failure behavior, not an ID stored forever in a preview. Existing Rename proves only that the repository has code using these boundaries; no successful native behavior is claimed here.

For recycle, the load-bearing documented chain is parsing name → Shell item → queued deletion → perform → abort query. The code's no-Permanent-fallback branch is established independently of the Shell's actual recycling behavior. The abstract swap is placed before Shell item construction; its internal behavior after construction remains unproven.
