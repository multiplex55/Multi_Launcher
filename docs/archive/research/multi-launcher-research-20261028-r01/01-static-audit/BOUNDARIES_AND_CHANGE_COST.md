# Boundaries and change cost — Goal 01 / M2-B

Baseline `59156d96adcc73939c7171487a0cb582e3286587`; static source/manifests/test-fixture inspection only. No compile, dependency resolution, profiling or application execution. Counts and module exposure identify ownership/review scope; they do not establish build time, runtime cost or a target size that a subsystem ought to have.

## Current dependency and ownership boundaries

The workspace already has an application package and `multi_launcher_table_core`. The app depends on that crate by path; the core manifest depends on `csv` and `serde_json`, and the application table facade is a re-export. The application package carries GUI/platform/plugin dependencies and patched egui/eframe/image/toast crates. Static imports, trait objects, `cfg` branches and patched callback behavior limit what an import graph proves about runtime execution. No crate-per-plugin or second table engine is justified. [B1], [B2], [B3]

The library exposes many first-party modules, while main and GUI coordinate those owners. Logical boundaries already exist inside one crate: typed command bus/hosts, Universal Action resolution/execution, shared search ordering, plugin snapshots/tickets, input authority, settings transactions, persistence catalog, native file evidence and utility sessions. A large file can still contain an existing owner; moving functions to another file changes navigation but does not alone reduce dependency exposure, retained memory or compiler work. [Source map](SOURCE_MAP.md), [architecture](ARCHITECTURE_AND_DATA_FLOWS.md).

## Test/build setup is a separate cost dimension

Cargo declares grouped `plugin_queries`, `domain` and `pure` test targets, while top-level `tests/*.rs` remain auto-discovered. Domain includes file-operation, File Search, command-bus, ranking and other side-effect-free cases. Choosing a relevant target can avoid unrelated test execution; it does not prove which dependencies Cargo will compile or how much linking costs. Unit-only inert constructors are `cfg(test)` seams; they cannot simply be called from every external integration target. Test placement must respect visibility rather than widening production API for convenience. [B4], [B5]

`PluginManager::new_inert_for_test_at` uses an empty Macro store and avoids process-global runtime/native catalog installation. `new_inert_for_test` still opens an isolated store; neither is synonymous with the full production constructor. Existing older fixtures that mutate CWD/environment or use production construction are reference cases, not a mandate for new tests. Future app fixtures must set Paste `next_hotkey = None` and `cancel_hotkey = None` before construction. This task changes no fixture, manifest or global configuration. [B5]

Features gate smoke/performance/QA binaries. Manifest comments describe iteration profiles as measured historical candidates, but this research ran no profile comparison and adopts no prior result as a measurement of the current source. Local vendor patches are existing product integration; unrelated vendor cleanup is excluded. [B1], [B4]

## Performance hypotheses: acceptance before optimization

No performance optimization is accepted from this audit. Source size, number of dependencies, a detached handle or an allocation site cannot be converted into a latency/RSS/build improvement percentage. Existing source has isolated synthetic search instrumentation and performance feature gates; their presence is neither a run nor an instruction to execute the historical campaign. [B4], [B6]

| Hypothesis / trigger | Minimum meaningful later experiment, only if separately authorized | Metric / identity controls | Rejection condition / current decision |
|---|---|---|---|
| A domain extraction would improve iteration time | First identify one repeatedly edited owner and one actual costly target. Compare baseline/candidate with identical Rust/toolchain/lockfile/profile/target; separate clean build from incremental single-owner edit. Use three repeated samples per preparation state, record commands/cache preparation and machine. | Wall time and compiler/link phase when available; exact source and edited-file identity, same dependency cache and background conditions. No mixed clean/warm aggregate. | If timing spread overlaps the claimed gain, changed target remains dominated elsewhere, or API migration cost exceeds demonstrated value, reject performance justification. **NO_ACTION now**; no extraction candidate established. |
| Search materialization/ranking dominates user latency | Goal 02 may define an isolated synthetic query workload; later production work must separately capture current provider snapshot and stable complete output identity, compare relevance/parity before elapsed time. | Named catalog/query sizes and provider state; warmups separately recorded; median plus range; output equality/eligibility and pending state. No application benchmark is authorized in Goal 01. | Reject if output authority/ranking compatibility changes unintentionally or observations cannot separate provider/native latency from pure ranking. This audit supplies constraints, no optimization package. |
| Cancelled File Search/refinement work accumulates materially | Trigger requires a concrete resource bound or complaint. Future focused owner fixture can stall one synthetic executor/read and issue a fixed small number of replacements/rescans, count live work and current publication; release every barrier and observe cleanup. | Distinguish maximum admitted/current queue from old still-running work, terminal events from return/join, logical payload from RSS. Native blocking needs a separate narrow proof. | Without harmful retention/required bound, preserve cooperative cancellation and stale rejection. A detached worker alone is insufficient. **CONDITIONAL_WATCH; no scheduled experiment or accepted backlog**. |
| Native file-identity protection has unacceptable overhead | Only after AUD-F002 chooses the required contract, compare metadata checks and selected stronger admission on a small synthetic disposable set, separately measuring hash/native admission if relevant. | Exact contract and data/identity sizes, pinned source/API/filesystem; no private documents. | Do not weaken required authority because a stronger unrelated transaction owner is expensive. Native performance is outside this spike; no current savings claim. |

This table states falsifiable evidence requirements if a real future request warrants work; it does not accept or queue four more experiments. The accepted catalog is finite in [RECOMMENDATIONS.md](RECOMMENDATIONS.md).
