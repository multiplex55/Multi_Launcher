# Track C deterministic owner workloads

This document defines the test-only fixture and sampling protocol for Track C. It does not define G0 or authorize optimization. C0-C smoke measurements are not the frozen baseline; C0-D must run only against the accepted, committed source and separately record the profile and source SHA.

## Isolation and mode

The `performance::track_c_workloads` module is compiled only for tests. It wraps the existing isolated-workspace guard, gives fixtures a separate Track C seed/signature domain, sets `ML_SKIP_CLIPBOARD_SYNC=1` before constructing an owner, and restores the environment and CWD before deleting the owned temporary directory. Declare the guard before apps, plugin instances, coordinators, and workers so they are dropped first. Benchmark commands must also set `ML_SKIP_CLIPBOARD_SYNC=1` at process creation; the in-test setting is a local backstop.

Set `ML_TRACK_C_BENCH_MODE=small` for bounded smoke fixtures or `full` for the documented G0 sizes. Any other explicit value is an error. The default is `full`, so commands intended for smoke runs must select `small` explicitly. Small-mode timings are never substituted for full G0 measurements. The historical `ML_TRACK_A_BENCH_MODE` and `performance::workloads` behavior remain unchanged.

Track C benchmark owners are ignored by default and are named `track_c_benchmark_*`. Ordinary deterministic fixture and oracle checks use `track_c_fixture_*` and `track_c_oracle_*`. The opt-in diagnostics switch is cached when the test process starts; enabled and disabled observations therefore require separate processes. No benchmark fixture executes launcher actions, native UI actions, Recycle Bin operations, or user-data paths.

## Fixtures and sample protocol

Track C fixture builders use a domain-separated seed and hash all fields, including `Option` presence and collection boundaries. Their inputs are synthetic notes, actions, or files beneath an owned temporary root. Full-mode target sizes are:

| Owner input | Full sizes | Small smoke |
|---|---:|---:|
| Note documents | 100, 1,000, 5,000 | 100 |
| Actions/results | 100, 1,000, 10,000 | 100 |
| Combined custom and indexed actions | 20,000 | 200 |
| Indexed files | 16, 1,000, 10,000 | 16 |

Each owner uses five warmups and twenty measured samples. Fixture construction, setup, cache publication, invalidation, oracle preparation, font settling, and cleanup are outside the timed interval. Direct owners time only the named production invocation. Root list/grid and Quick Notes frame owners include the `egui::Context::run` wrapper around the actual production render call; their returned `FullOutput` remains alive until after the timer stops. These are headless egui CPU-frame measurements. Immediately after every invocation and after the timer stops, the test compares the complete result and relevant state with its independent eager reference. It retains each sample, even when it differs in duration; it does not replace a distribution with a final-run result. Quantiles use nearest rank: `ceil(p * n)` in one-based sorted order. Reports preserve all twenty elapsed values, output/state identities, viewport receipts, and work counters.

The output/state identity is separate from a viewport receipt. A viewport receipt describes only visible widget/layout state and cannot stand in for the complete ordered catalog, note rows, or owner state. Mutable revisions are checked against each sample's expected state and retained as raw revision receipts; they are not forced to remain numerically identical across repetitions. Reports include fixture signature and size, effective mode, actual cached diagnostics state, source provenance (`ML_TRACK_C_SOURCE_SHA` or `UNCOMMITTED_SOURCE`), injected Cargo profile (`ML_TRACK_C_PROFILE` or `unspecified-profile`), viewport, scale, font state, settings, and cold/warm classification. An uncommitted source or unspecified profile is smoke evidence only.

## Frozen references and owner boundaries

Notes compare all seven `BacklinkRow` fields in order, the complete todo label map, and note/todo revisions. The eager reference is test-local and keeps the pre-optimization relationship rules. Search compares every ordered `Action` field, preserving the distinction between `args: None` and `Some("")`, plus provider/pending state and catalog-version receipts. Controlled providers use a captured result snapshot shared by expected and production paths; ordinary provider behavior is exercised in a separate call so a stateful provider is not invoked twice to manufacture an oracle.

The note workload retains the seeded 4 KiB/32 KiB body-size variation and sparse references. Its related Unicode-body row verifies a real Unicode snippet with valid UTF-8 slice boundaries; a separate catch-unwind case records the existing invalid-boundary panic without changing production semantics. A fenced-only `@note:` needle and a truly unrelated row must remain absent. Fenced wiki syntax is intentionally excluded from that probe because `NoteCache` resolves wiki links from raw content before the panel filters fenced prose. The combined note/todo fixture signature includes the complete ordered todo ids, text, done/priority, tags, and typed entity references. Existing focused behavior coverage is reused instead of copied into the timing harness: `unchanged_heavy_check_skips_note_snapshot_alias_hash_and_recompute`, `edits_do_not_trigger_heavy_recompute_every_frame`, `new_draft_after_failed_refresh_uses_normal_edit_debounce`, `pending_external_mutation_without_edit_time_refreshes_immediately`, `persisted_note_revision_bypasses_local_edit_debounce`, `open_unsaved_panel_tracks_external_note_and_alias_transitions`, `todo_revision_change_bypasses_local_edit_debounce`, `persisted_todo_text_and_note_reference_refresh_linked_rows`, `backlink_setting_transitions_rebuild_only_when_enabled_and_preserve_rows`, `failed_heavy_snapshot_retains_rows_and_retries_after_cooldown`, and `backlink_rows_ignore_fenced_code_links`.

Search owner fixtures cover sparse exact alias collisions with tied usage, dense exact empty-term results, dense fuzzy results, empty-query browsing, and provider-pending results. Their input signatures include the full local/provider/command action state, query, aliases, usage map and weight, and exact/fuzzy settings. Existing focused semantic coverage is reused for `search_replacement_clears_selected_index`, `exact_display_match_uses_pre_normalized_query_substring`, `exact_mode_keeps_plugin_resolved_results_but_filters_query_suggestions`, `manual_query_fallback_does_not_reenter_a_blocked_provider`, and `clipboard_modify_root_query_returns_direct_open_modify_first_in_fuzzy_mode` plus its exact-mode companion.

The Actions publication owner writes one deterministic changed custom-prefix payload before timing, then measures the real `LauncherApp::process_watch_events` reducer for one `WatchEvent::Actions`. The owned fixture combines a custom-first prefix with an indexer-generated retained tail (200 actions in small mode, 20,000 in full mode); its first custom id deliberately duplicates the first tail id. Each sample compares the complete ordered `Action` values and `args`, exact custom boundary, independently derived cached search entries and filter metadata, last-wins id map, full current search results, selection and query validity before computing a path-normalized structural digest. Only owned indexed paths in all path-bearing projections are normalized, and only after full raw `Action` equality succeeds. Action-store and plugin-catalog revisions are recorded per sample rather than folded into structural identity. Its `work_units` value is the complete catalog entry count; work counters are `[custom prefix entries, retained indexed-tail entries, cached search entries, filter metadata entries, unique action-id entries, full search results]`. These counters are complete output collection lengths, not measured constructor, clone, or per-item processing counts. The owner interval includes typed JSON read, unchanged-tail preservation, cache projection publication and synchronous query refresh; filesystem fixture traversal, payload writes, enqueue and oracle comparisons remain outside it. The ordinary `track_c_oracle_actions_reload_preserves_catalog_and_last_good_state` case checks complete derived state after changed, unchanged, malformed, missing-file and recovery notifications, alongside Arc/version retention and one recovery version bump.

Owner counter arrays have fixed documented orders. Note refresh counters are `[refresh calls, three-pass note visits, mention scan calls, mention note visits]`; `work_units` is the three-pass visit count. Search counters are `[phase catalog visits, candidates scored, local hit Action clones, final results moved]`; `work_units` is candidates scored plus final results moved, and does not describe allocations. For empty-query browse, `0:0:0:0` means the two instrumented scoring/materialization phases were bypassed; the browse still clones the command cache and materializes prefixed catalog Actions. The output identity and full Action comparison remain the correctness evidence.

Root list/grid and Quick Notes geometry use eager variable-height/global-column oracles in independent egui contexts. The actual scaled UI supplies the root viewport width, and the actual Quick Notes scroll area supplies its viewport size; neither oracle derives dimensions from the geometry cache under test. Oracle contexts never warm a measured production context. Quick Notes input signatures retain the raw ordered note fixture, while expected projection, metadata, and rows come from one versioned snapshot of the canonical published cache; ordered slugs are checked across that boundary. Repeated geometry-cold samples invalidate the real owner cache after fonts and the atlas have settled; reports call this **geometry cold / warm fonts**, not fresh-process first-open. Warm samples assert no full geometry measurement. Root list/grid visible widget indices are compared with the independently eager-derived viewport plus overscan set, including grid visual spill rows; Quick Notes compares its original-index row projection and every built widget rectangle. The existing `root_grid_tall_cell_spill_stays_visible_without_intermediate_rows` and `root_grid_geometry_matches_settled_grid_cells_and_global_extents` tests retain semantic coverage for tall-cell spill and settled grid extents; the timed default-style two-line action fixture does not claim to measure a tall-spill workload. Full output/projection identity and the visible viewport receipt are recorded separately. Quick Notes keeps the twelve existing filter/height records and adds one empty-filter horizontal cold/warm pair per fixture size, covered by `track_c_oracle_quick_notes_horizontal_width_transition_matches_frozen_eager_geometry`. That pair settles at 960×640 and transitions in the same egui context to 300×640; it verifies the real ScrollArea width decreases, the geometry key changes and rebuilds, and the narrow complete projection, metadata, eager rows, widget rectangles and full extent still match. `TRACK_C_WIDTH_RECEIPT` records each measured narrow ScrollArea width in milli-points, separately from the screen-size viewport label; it is not a claim that the row width equals the screen width.

Geometry owner counter arrays are `[geometry rebuilds, full rows or cells measured, visible widgets built]`; root list/grid use rows/cells respectively, and Quick Notes uses projected note rows. The exact eager-derived visible set also establishes the owner-specific paint bound. It replaces a universal widget-count threshold because a grid row contributes its configured number of cells. The query-to-frame composite uses the typed suffix `00009` against the synthetic action ID `synthetic:action:00009`; it clears constructor-provided host folder/bookmark entries before settling fonts or searching. Its counters are `[catalog actions, candidates scored, local Action clones, final results moved, geometry rebuilds, full rows measured, visible rows built]`; `work_units` is candidates scored. The timed closure sends text through the production launcher `TextEdit`, so its query mutation and synchronous search occur before the same real root render completes.

The required production boundaries are the note panel's heavy derived refresh, the shared read-only launcher search outcome with controlled provider snapshots, `render_root_frame` for list/grid and the root query-to-current-usable-frame path, `NotesDialog::ui`, `process_watch_events` for Actions and injected index completion, actual channel dequeue/drain, and binary `startup_action_catalog`. Startup catalog assembly does not measure OS process creation, plugin-ready latency, native presentation, or time-to-display.

The binary-local `track_c_oracle_startup_action_catalog_matches_complete_acknowledged_output` and ignored `track_c_benchmark_startup_action_catalog_owner` invoke the real private `startup_action_catalog` boundary with 16, 1,000, or 10,000 synthetic indexed files (small mode uses 16). The fixture owns one flat temporary root, deterministic file payloads, a three-entry custom prefix, and an exact `IndexConfig`; all construction, writes, input signatures, and config/custom clones happen before timing. A separate direct `read_dir` enumeration builds the expected indexed Actions in filesystem order. After each invocation and after its timer stops, the harness compares the entire ordered custom-first catalog, all Action fields and args options, prefix boundary, indexed path membership/order, transfer generation/config, successful `validate_acknowledged_result`, and the consumed-result `take_result() == None` state. Only after raw equality succeeds does the structural digest replace the owned canonical root prefix with `$TRACK_C_ROOT`; raw complete-output IDs retain actual paths and can vary with the temporary root.

The measured interval includes construction of the startup coordinator, filesystem traversal, completion wait/acknowledgement, and custom-first catalog assembly. Oracle work, transfer validation, digesting, and dropping the completed coordinator are outside the interval; each transfer/coordinator is dropped before its owned temporary workspace. Five warmups precede twenty measured samples for each size. Since those warmups traverse the same fixture, `cold_type=new_coordinator_warm_os_cache` identifies a new coordinator over a warm filesystem cache; these samples are not first-use disk measurements. `work_units` is complete catalog length and counters are `[custom prefix entries, indexed tail entries, complete catalog entries]`. The existing startup test's restricted OmniSearch fixture still checks initial custom/index query behavior; the timed owner stops at catalog assembly and makes no claim about plugin registration/readiness, OS process startup, hotkeys, native services, first frame, or display time.

Event-age samples are captured by a channel-local test-only fixed-capacity recorder at successful dequeue. The app's standard channel is unbounded; the recorder capacity is only an observation cap, not a production queue limit. Under its local recorder lock, the test seam also acknowledges successful sends only after `mpsc::Sender::send` commits, so queue-depth synchronization waits on that receipt rather than a depth reservation. Send acknowledgment and all queue setup remain outside owner intervals. Drain and event-age measurements include this bounded test-recorder instrumentation, which must remain unchanged for G0/G1 comparisons. Each delivered sample contains only numeric nanoseconds and static event class/origin. Abandoned envelopes are counted separately and excluded from delivered-event age quantiles. The recorder's overflow count must remain zero; overflow invalidates that sample set. Reset only after producers are quiescent and the prior queue is resolved, or create a fresh channel and recorder. Queue burst means/maxima remain separate from the per-event age distribution. Residence in pre-owner registry bookkeeping is outside app-channel age and is `NOT MEASURED` unless separately instrumented.

The ordinary `track_c_oracle_original_index_ready_merges_latest_prefix_and_ignores_stale_wake` case covers both latest-prefix publication and stale-generation rejection using coordinator-produced original envelopes. The finite watch-queue owner, `track_c_oracle_finite_watch_burst_preserves_fifo_and_state` / `track_c_benchmark_watch_event_finite_burst_owner`, times the actual `LauncherApp::process_watch_events` reducer on a fixed sequence containing one changed Actions notification, the coordinator's original `IndexReady` for candidate A, unchanged Actions duplicates, and a successful `Recycle(Ok(()))` completion with toasts disabled. Candidate A deliberately differs from the current indexed tail so an incorrectly accepted stale result fails full catalog parity. After A's send is acknowledged, the fixture submits generation B and holds B at a scanner gate before reducing A; this ensures A's original envelope remains queued and is stale under the live generation. The measured drain consumes A through the ordinary reducer, then validates the complete action/cache/filter/id-map/search state, exact FIFO class/origin order and queue depth zero. The reported primary age rows stop at this drain. On successful samples the fixture then releases B, waits for B's original completion notification, drains it outside the owner receipt and verifies equal-tail `Arc`/version retention, final depth zero, and no overflow or abandonment. Every gate has a release-on-drop guard that unblocks its scanner before owner teardown; successful samples also await completion and consume the cleanup notification before app/workspace teardown.

For this finite owner, event age includes the intentional residence of A's queued notification while generation B is submitted and reaches its scanner gate; this is part of the actual send-to-dequeue age, even though setup and waits are outside the reducer timer. Treat it as a gated stale-notification scenario, not a production steady-state queue-lag estimate. The separate `track_c_oracle_concurrent_watch_producer_drains_finite_offered_load` / `track_c_benchmark_watch_event_concurrent_offered_load_owner` cases send a finite sequence of Actions notifications plus one toast-disabled recycle completion; they do not synthesize an `IndexReady` event. The recycle completion only exercises its GUI receipt and never invokes cleanup. A scoped producer guarantees it finishes before fixture validation or unwinding can tear down the owner/workspace. Concurrent arrival order is not claimed; the producer's own sequence and final state are checked.

The finite and concurrent owners use five warmups followed by twenty measured samples, and assert complete state after each sample's full drain sequence and final queue depth zero. Each sample gets a fresh observed channel; the fixed age-recorder capacities are 16 for the eight-event stale-index receipt plus B cleanup, and 32 for the fourteen-event concurrent receipt. Their work counters are `[total delivered events, Actions events, IndexReady events, recycle completion events, custom prefix entries, indexed tail entries, complete catalog entries, cached search entries, filter metadata entries, unique action ids, search results]`; these are complete output sizes and delivered counts, not cloned/handled object counts. For the finite stale-index owner, the primary measured sequence has eight events at every catalog size: six Actions, one original stale coordinator completion and one recycle receipt. The later equal B completion is drained outside that primary receipt. The concurrent owner offers fourteen events: thirteen Actions (one prequeued plus twelve from its producer), no `IndexReady`, and one recycle receipt.

For the concurrent owner, `TRACK_C_RESULT.elapsed_nanos` is the sum of actual `EventDrain` phase intervals around reducer calls. Producer thread spawn, barrier waiting, and scoped join are outside those timers; producer scheduling, preemption, and recorder contention during active reducer intervals can still affect them. `TRACK_C_EVENT_AGES.drain_ns` reports the same summed reducer interval for the sample. Keep this measured boundary matched in G0/G1 comparisons. Both owners emit one `TRACK_C_EVENT_AGES` row per measured sample, with all primary-interval per-event `age_ns` values in dequeue order and parallel `classes`/`origins` arrays, nearest-rank p50/p95/max, complete output and structural identities, reducer call count and `drain_ns`, class/origin `handler_receipts`, recorder capacity, overflow and abandonment. The finite stale-index row intentionally excludes B's later cleanup notification; the test still consumes it and checks the full recorder's terminal counts before fixture teardown. These rows join to `TRACK_C_RESULT` through owner, source, profile, mode, fixture signature, cold type and sample index. Age, handler, and drain receipts remain separate measurements. The channel recorder capacity is metadata for the test observer, never a production queue bound.

## Safety and evidence limits

Synthetic settings disable hotkeys and the dashboard, providers are inert except controlled local fixtures, and all paths resolve beneath the test workspace. No action is activated as part of search, rendering, publication, queue, or startup measurements. In particular, never select `recycle_plugin::command_returns_immediately_and_cleans`; it has a real Recycle Bin side effect and remains ignored.

Headless egui measurements characterize owner CPU and layout work only. They are not evidence of Windows input, native composition, GPU presentation, or pixels reaching the display. The native recipe and user-data cleanup campaign remain parent-owned and are not run by C0-C smoke tests. G0 is not frozen by this document or by small-mode output.
