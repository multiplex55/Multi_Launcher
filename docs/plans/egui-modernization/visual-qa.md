## Isolated fixture design

`prepare_native_fixture.rs` writes a one-run workspace beneath the ignored path `target/egui-modernization/native-baseline/run-<id>`. It refuses an existing run directory and never removes files. It calls `Settings::save`/`Settings::load` and the `Action` serde JSON serializer, then checks generated settings and actions by reading them back. For a new run, the exact linked libraries are bound by the build receipt described below; source code alone does not establish which compiled library an older helper used. It writes ordinary UTF-8 Markdown notes in the format consumed by `plugins::note::load_notes`. No hand-edited sparse settings object is used.

Default preparation counts are 1,000 synthetic actions and 100 synthetic notes; the helper accepts bounded count overrides up to 10,000 actions and 5,000 notes. Action IDs use only the in-app `query:<synthetic-text>` command. Activating one only changes the launcher query; no fixture action starts a process, opens a URI/file, writes outside the workspace, or mutates clipboard data. Notes contain generated headings and plain synthetic paragraphs without links, tags, external images, or user data. The revised `build_fixture_helper.ps1` requires explicit `multi_launcher`, `serde_json` and `sha2` rlib paths via `-LauncherRlib`, `-SerdeJsonRlib` and `-Sha2Rlib`, selected from the parent's Cargo JSON build receipt. It validates the files and writes a sidecar containing each selected library's SHA-256 plus helper source and executable hashes. Pass the printed sidecar path as the generator's final `<build-receipt>` argument; the generator checks that it names the running helper hash, copies it into the run directory and binds its hash into `fixture-manifest.json`.

For the current Cargo JSON receipt at `target/egui-modernization/baseline/build-fast-dev.jsonl`, the launcher artifact is the exact canonical `target/fast-dev/libmulti_launcher.rlib`; the helper accepts that path or a correctly named hashed launcher rlib directly under `target/fast-dev/deps`. `serde_json` and `sha2` must be explicitly supplied as their correctly named hashed rlibs under `target/fast-dev/deps`. The helper records the exact selected paths and SHA-256 hashes. The fixture generator validates those narrow path/name forms; it does not infer artifact selection from directory contents or select the newest library. The earlier `run-original-001` and `run-original-002` manifests remain unbound to these helper/library receipts as described below.

The existing `run-original-001` and `run-original-002` fixtures predate this explicit binding. Their manifests verify the app executable hash, but contain no helper executable hash or selected-library receipt; the previous script chose rlibs by last-write time. Their serializer round-trip checks were observed, but exact serializer-library provenance is **unverified**. Keep that limitation attached to these two runs. Each contains 1,000 actions and 100 notes; see their manifests and process receipts under ignored `target/egui-modernization/native-baseline/`.

The native launch shell must set process-scoped variables before starting the child and restore the shell's prior values immediately afterward:

```powershell
$env:ML_NOTES_DIR = (Join-Path $fixtureRoot 'notes')
$env:ML_NOTE_TEMPLATES_DIR = (Join-Path $fixtureRoot 'templates')
$env:ML_SKIP_CLIPBOARD_SYNC = '1'
$env:MULTI_LAUNCHER_PERF = '1'

```

Use a `try/finally` around the assignments and `Start-Process`, saving and restoring each prior process environment value, including the distinction between unset and set. Do not change user or machine environment. `ML_NOTES_DIR` is essential: without it, notes default beside the executable. `ML_NOTE_TEMPLATES_DIR` prevents note-template reads or writes under the user's home directory. `ML_SKIP_CLIPBOARD_SYNC=1` prevents clipboard synchronization/mutation.

The app resolves relative `settings.json`, `actions.json`, history, usage, favorites and other ordinary stores from its current working directory. `AppDataRoot::from_settings_path("settings.json")` also derives the radial store and single-instance identity from that root. This is a **root-only fixture**: common plugin surfaces such as Notes, File Search and MKMacro require a separately reviewed fixture with the necessary explicit enabled-plugin IDs; no plugin QA result may be claimed from this minimal profile. It redirects screenshot and dashboard configuration paths into the fixture and disables logging. Built-in read-only dashboard refresh remains part of normal application behavior even when dashboard presentation is disabled; do not publish any dashboard contents in shared receipts or screenshots. No production bypass is added.
