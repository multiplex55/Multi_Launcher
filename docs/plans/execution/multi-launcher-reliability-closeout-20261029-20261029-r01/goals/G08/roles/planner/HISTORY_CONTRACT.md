## Observed owners

- `src/mkmacro/runtime/summary.rs::SummaryHistory` is the only completed-run store. It owns a `VecDeque<MacroRunSummary>`, revision, used/active byte accounting and finite limits: 100 completed records, 4 MiB metadata, 1024 step aggregates per run; captured name bound is 256 UTF-8 bytes. `reserve_active` may evict oldest completed records for execution work. `publish` transfers accumulator accounting to a terminal record. `MacroRunSummary` intentionally has no Clone.
- `SummaryHistory::with_completed`, `MacroRuntime::with_run_summaries` and the global `runtime::with_run_summaries` lend records while locked. The global helper also currently retains the global RUNTIME read guard through its callback. No production history UI caller was found.
- `MacroRuntime::with_guard_and_clock` already assigns `generation` from `RUNTIME_GENERATIONS`; each runtime starts `next_run_id` at 1. Reuse `(generation, run_id)` for a typed `RunKey`. Run ID alone is not stable across runtime replacement; a deque index, macro ID or timestamp is not a run identity.
- `submit_command_with_owner` begins summary accounting only on admission. A busy/pre-admission rejection is not a completed run. `RootRunGuard::{complete,drop}` publishes terminal outcomes and preserves source/origin/mode/subset. Existing pause and terminal classifications stay authoritative.
- `src/gui/mkmacro_dialog/mod.rs::MkMacroDialog`, `ui_with_jump_mode_synced`, `show_contents_with_table_viewport`, `close_children`, and `toolbar::show_with_jump_mode` own dialog visibility/rendering. History belongs in this dialog. Existing `runtime_inspector_snapshot` retains variables and arbitrary diagnostics for its separate debug purpose; it is not a history data source or retention pattern.
- Existing `InvocationSource::label`, `SummaryActionCategory::label`, `SafeFailureLocation::safe_reason` provide safe finite labels. Display captured attribution exactly; do not invent a Radial enum variant or infer source from the current UI.

## Chosen bounded display contract

Keep `MacroRunSummary` and canonical history ownership unchanged. Add a crate-private, non-Clone, frame-scoped projection API inside the summary/runtime owner. It projects only the allowlisted metadata needed for one visible history page and one detail page. It is not a second history, a clone of a full summary, an Arc record, a persistent snapshot or a public arbitrary-record copier.

Initial presentation bounds: at most 20 run-list headers, at most one additional selected-run header if off-page, at most 64 selected step aggregates, each displayed name bounded to the existing 256-byte limit. Project names as bounded plain display text; replace control/formatting characters that could create misleading rows and retain a truncation indicator. No full `step_aggregates` Vec or runtime snapshot leaves the store. Use fixed/bounded storage; actual retained capacities, inline storage and the lease itself have an explicit byte charge. The implementation must calculate its charge from its real types/capacities, not assume a count of characters equals allocated bytes.

Projection acquisition and release are owned by the same SummaryHistory instance:

1. A visible History render requests one page, finite outcome filter and optional RunKey. Acquire at most one frame-view slot per runtime. Check/reserve its complete byte charge against the existing 4 MiB total **before** allocating/copying. Do not call `reserve_active`, evict records, reduce active accounting, borrow a second budget or change execution admission merely to fund a read. If no headroom/slot is available, return a safe typed unavailable/busy view and let the UI show it without polling.
2. Copy the bounded allowlisted projection and captured history revision while holding the history mutex briefly. Keep projection bytes charged separately from active-run bytes. Release both history and global runtime registry locks before egui layout, font work, callbacks or rendering.
3. The view lives only for that render operation and is dropped before the frame returns. The renderer may not return/store its rows, names, vectors or other metadata in MkMacroDialog, egui persistent data, closures, a global or another Arc. Persistent dialog state contains only open/view choice, RunKey, finite filter and page/scroll choices. Format strings are bounded render temporaries, not caches.
4. Worker publication/eviction proceeds while the view is rendered. Canonical records remain exclusively owned by SummaryHistory and can be evicted normally; no evicted MacroRunSummary survives through a reader-owned reference/clone. A frame projection is an explicitly charged point-in-time selection of display values, not a claim that those records are still present. Its charge remains until the render ends even if its original row is evicted or cleared. No action may be authorized from that projection.
5. Lease release/Drop returns exactly its charge to its original history owner, including unwind paths; it must not subtract active/completed charges. A runtime registry replacement cannot make release touch the new generation. A short-lived runtime owner reference is permitted for this frame lifetime, but the dialog must not retain the old runtime/history. A second view request while occupied fails safely. A callback/lifetime-shaped API is preferred to making a persistable owned view generally available.

The no-Clone invariant is not satisfied by renaming an entire summary to a view. Review the actual fields and escape paths. Existing count/row bounds remain canonical limits; the additional bounded presentation storage must also remain within the same total-byte limit. No hidden eviction for display is allowed.

## Visible behavior and lifecycle

Provide a History view reachable from the existing MkMacro dialog, with newest completed records first by publication order, not wall-clock sorting. Default selection is the newest retained record. Show captured macro name (or fixed fallback), run identity, outcome, elapsed and paused duration, source, origin, normal/debug mode, whole/from/selected subset and visit totals. Optional paged details contain numeric macro/step IDs, action category, counts and inclusive elapsed only. Display omitted-detail/truncation/counter-overflow markers truthfully. Running/paused jobs remain in existing runtime controls; do not fabricate terminal rows. Busy admission refusal is not a history event.

Use finite outcome filtering and bounded paging; no need for a new search/index/sort engine. A selected RunKey stays selected across publication/filter/reordering if still retained. If evicted, cleared or from another generation, discard selection/details or show a fixed no-longer-retained state; never bind to a reused numeric ID. Captured names do not depend on the macro still existing in the current authoring document.

Clear, if exposed as planned, clears completed history only through SummaryHistory. It does not change an active accumulator, run ID, run control, store, draft or current run. A running job may publish its terminal record afterwards. Clear advances revision and subtracts only removed completed charges; a live frame-view charge and active bytes remain. Queue the user action from rendering, release the frame lease, then apply it to the captured runtime generation. Refuse a stale-generation clear rather than clearing an unrelated replacement runtime.

Acquire history only while its panel is actually visible. No history call from constructor, hidden dialog, `sync_external`, global application update or inactive Editor view. Rendering an otherwise requested visible frame may read current bounded data; do not add timers, worker polling, subscription threads or `request_repaint_after`. Opening, paging/filtering/clearing and ordinary input provide demand. Close drops transient presentation data and leaves the memory-only canonical history intact; reopening requests current data.

History is in-memory only and is not serialized by MkMacroStore. Opening, filtering, selecting, closing and clearing must not dirty the draft or execute a macro. No raw steps/actions, keystrokes, clipboard/OCR text, pixels, arguments, variables, file contents, arbitrary diagnostic strings or existing `command_error` enter the history view or logs. Name metadata is the existing bounded user-authored name, not a guarantee that a user never chose a sensitive name. Do not add raw-name logging or tooltips containing excluded payloads.

## Preservation and proof

Preserve Run/Stop/Pause/Resume, debug, nested calls, recording review and existing source attribution. The new surface may not call the executor, invocation preparation, recorder or store save. Existing toolbar commands remain the only execution controls on this surface; no Run Again/Recipe button is introduced.

One implementation checkpoint combines user-visible history and ownership/lifecycle proof. Required evidence includes frame lock release with concurrent terminal publication, byte accounting through clear/eviction/Drop/runtime replacement, bounded selection/paging, no hidden acquisition/repaint loop and no-secret UI projection. Use inert local runtimes and egui state tests; no new native API contract warrants an app build or native campaign. Native evidence is NOT_RUN, not a blocker for this ordinary GUI feature.

Confidence is high in the owner map and design path. The current callback API cannot itself meet the unlocked rendering contract; the bounded charged projection is the necessary ownership adapter, not permission for a second store.
