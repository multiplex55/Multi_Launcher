Current source already has explicit **authoring templates**: `src/mkmacro/templates.rs::MkMacroStore::{save_macro_template,load_template_catalog}`, `plan_template_instantiation`, and `src/gui/mkmacro_dialog/package_ui.rs::{show_toolbar_menu,apply_plan}`. The Reuse menu offers Save as Template and New from Template; the user previews and explicitly creates an independent copy. Template copies receive fresh identities, have all copied macro hotkeys cleared, and do not auto-run. These existing facilities must remain intact. Their presence is counterevidence to a claim that MkMacro has no safe reuse workflow.

Those templates capture a macro-definition package and assets, not a terminal-history run invocation. `src/mkmacro/invocation.rs::MkInvocation` carries transient arguments/mode/subset; `prepare_parameters`, invocation compilation and runtime admission validate current requests. `MacroRunSummary` intentionally does not retain arguments, secret values, complete selected-step identities or executable action data. A history record cannot reconstruct or authorize that invocation. Current source search found no Recipe model or defined policy for saving history-derived invocation presets, retargeting changed macros, retaining arguments, confirmation or permission scope. Absence is scoped to inspected owners, not a claim that a broader audit proved impossibility.

Do not add Run Again/Recipe shortcuts, copy historical values from debug snapshots, introduce a new persistent store, or relabel templates as proof of a new history-invocation authorization contract.
