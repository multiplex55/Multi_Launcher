### Outcome and analytical contribution

The production system already has a substantial search stack. Its route selection, provider admission, returned-result filtering, command fallback, local `app` scoring, usage addition, completion and activation must remain distinct. A discovery feature added to `self.results` or command cache would change real automatic consumers before an interactive-only guard could protect them. The settled research seam is a **separate presentation projection** over fixed metadata, not a new provider, canonical ranker replacement or dispatcher.

The authored [architecture report](../../CURRENT_SEARCH_ARCHITECTURE.md) makes the closed audit corrections explicit in a route matrix. In particular, g bypasses command fallback; non-g empty input provider vectors can fall back before exact post-filtering; post-filter-empty does not retry; capacity deferral composes already-scored empty providers directly; failed-provider reopening separately uses the scorer and can fall back. This distinction matters to later admission: row-empty is neither no-work nor proof a query has no owner. Pending/deferral/catalog stability remain separate gates.

The capability catalog's contribution is exact **tool-opening** contracts, with stable research IDs and owner evidence. Eleven planner seeds across nine owners plus four research-only Diff/File Search openers across two owners give 15 descriptors. This is deliberately enough object/intent overlap for later evaluation without migrating all plugins. Format/minify are mode intents; `json pretty` is an existing alias for format. File Search filename/content are mode-only openers, not searches; their typed start/request-directory paths stay separate. Empty Diff has two null paths; no inferred input or operation is allowed. Catalog construction performs text serialization, not action resolution.

The additional four are not part of SEARCH-F001's raw proposed shipping scope. Full and initial-subset comparisons must retain identical case denominators/labels and show absent targets rather than dropping extra-owner cases. If future evidence favors shipping them, M3-A must amend the canonical scope/owners/tests or leave them nonshipping research. This prevents catalog enrichment from falsely establishing relevance for an eleven-descriptor implementation.
